# ADR 0004：默认热键

[English](../../en/adr/0004-default-hotkey.md)

## 状态

采纳。默认绑定是右 Alt（`RAlt`），按住说话。

## 背景

Type4Me 的手势是「按住 Fn」。在 macOS 上，Fn 对 `CGEvent` 可见。在 Windows 上通常不可见。多数笔记本固件在 Fn 变成虚拟键之前就处理掉了它，少数会发出扫描码的机器也不统一。因此 `WH_KEYBOARD_LL` 不能把 Fn 当成可移植的默认键。

`RegisterHotKey` 不适合按住说话。它在和弦第一次按下时触发，对「只有修饰键」的和弦给不出可靠的松开。MVP 在自己的线程上安装 `WH_KEYBOARD_LL` 并跑消息循环，边沿判断放在纯函数里，同一套规则可以做单元测试。

## 决定

默认是**右 Alt**，按住说话。

- 它是单键，比组合键更接近「按住 Fn」。
- 钩子在普通硬件上能看到 `VK_RMENU`，并且能区分左右，所以左 Alt 和 Alt+Tab 仍然可用。
- 右 Alt 被设成绑定时，钩子会吞掉它，焦点应用不会因此打开菜单。

**Ctrl+Win** 是内置预设，不是默认。两个键钩子都能看见，而且只在 Ctrl 已经按下之后才吞掉 Win 键，所以单独的 Win 键仍能打开开始菜单。代价是冲突：Ctrl+Win+左右方向键用来切换虚拟桌面，和弦在方向键之前就已经成立，听写也会被启动。右 Ctrl 是另一个预设，给想要单键、又不用 Alt 的人。

## 后果

- 在右 Alt 就是 AltGr 的键盘布局上，按住它听写没问题，但无法再用 AltGr 打特殊字符，因为这个键被吞掉了。这些用户应在设置里改成 `Ctrl+Win` 或 `RCtrl`。绑定是 `config.json` 里的字符串，保存后不用重启。
- 不提供 Fn。以后可以为某台机器加扫描码，但那不会成为默认值。
