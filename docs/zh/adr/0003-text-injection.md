# ADR 0003：文字注入

[English](../../en/adr/0003-text-injection.md)

## 状态

MVP 采纳。

## 背景

焦点所在的应用应该像用户打字一样收到转写。直接改剪贴板再粘贴会冲掉用户刚复制的内容。也有应用处理不好 `KEYEVENTF_UNICODE`，所以仍然需要粘贴这条路。

Windows 的用户界面特权隔离（UIPI）不允许中等完整性的进程向更高完整性的窗口发送输入。「以管理员身份运行」的程序完整性更高。即使提权窗口把事件丢掉了，`SendInput` 仍可能报告已经写入。正规的修复是带 `uiAccess="true"` 的签名二进制，并安装在 Program Files 这类受信任路径。签名不在这一版范围内。

## 决定

主路径为每个 UTF-16 码元发一对 `KEYEVENTF_UNICODE` 按下/松开，所以非 BMP 字符会以代理对发出。换行变成 Enter 键，而不是一个换行字符。

默认的 `auto` 先调用 `SendInput`。如果返回的数量少于请求的事件数，就改走剪贴板：有 `CF_UNICODETEXT` 时先保存，再写入转写、发送 Ctrl+V、短暂停顿，然后把保存的文本写回去。`unicode` 从不碰剪贴板。`clipboard` 总是粘贴。

注入之前，应用最多等 200 毫秒，直到热键的修饰键松开，避免按住的 Ctrl 把后续按键变成快捷键。

## 后果

- 普通应用能收到文字，常见情况下不会丢掉一段文本剪贴板。
- 回退只恢复 Unicode 文本。如果回退发生时剪贴板里是文件或图片，那些内容可能丢失。
- 提权的目标窗口要到第四阶段（签名和 `uiAccess`）才能用。应用无法可靠地发现这种静默丢弃，所以把限制写在文档里，而不是用重试掩盖。
